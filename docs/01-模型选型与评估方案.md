# MUSE Studio｜模型选型与评估方案

> 版本：v1.2 · 2026-11-04  
> 文档类型：模型选型方案与评估计划  
> 适用范围：电商素材与批量短剧的线上模型服务  
> 当前阶段：已完成本机开源集成与少量真实 DeepSeek 验证；正式模型评估待执行，文中阈值为拟定验收标准。

## 1. 项目目标与选型结论

MUSE Studio 面向电商素材与短剧创作者，目标是缩短从需求输入到可交付成果的制作流程，同时保证商品信息准确、叙事连贯、过程可编辑及成本可控。

模型方案采用 **DeepSeek 负责创意与脚本，独立图像、视频服务负责视觉生产，确定性工具负责排版与导出**。选型依据包括业务质量门槛、结构化输出稳定性、端到端延迟、每份合格交付成本和接口可维护性。

- 电商：商品信息辅助理解 → 用户确认事实 → 创作 brief → 背景生成／编辑 → 商品层合成 → 文案排版 → 多尺寸导出。
- 短剧：故事结构 → 角色卡 → 分镜脚本 → 用户确认 → 分镜图 → 单镜头视频 → 剪辑拼接。
- 原交互原型使用预置示例；新增集成版已接入真实 DeepSeek 创意与四镜头脚本并记录用量。图像／视频模型尚未配置，正式评测仍需冻结数据集后执行。

## 2. 候选方案与角色划分

以下是基于官方文档的接入候选，不构成效果排名。

| 任务 | 首选候选 | 备选／升级路径 | 选择依据与限制 |
|---|---|---|---|
| 创作 brief、提示词、常规分镜 | `deepseek-flash` | `deepseek-v4-pro` | Flash 作为默认入口；复杂故事结构再评估 Pro 的增益，升级依据须来自相同测试集 |
| 商品图片信息辅助提取 | `deepseek-flash` 的图片理解 | 用户手工填写商品事实 | 当前官方文档支持图片输入；识别结果不能自动当成真实商品参数 |
| 商品场景图与分镜图 | FLUX.2 [pro] 在线 API | FLUX.2 [flex] | 官方提供生成和编辑、多参考能力；是否满足包装与角色一致性需实测 |
| 静帧到短视频 | Runway `gen4.5` 图生视频 | 固定镜头运动与静帧剪辑交付 | 官方提供图生视频及异步任务接口；不是 DeepSeek 的图像／视频输出能力 |
| 排版、尺寸、拼接 | 确定性渲染／媒体处理 | 人工编辑 | 文案排版、裁切、图层、编码不必交给生成模型 |

DeepSeek 的模型名称和版本对应关系按官方 2026-11-04 页面记录：`deepseek-flash` 对应 DeepSeek-V4.1-Flash-1017，`deepseek-v4-pro` 对应 DeepSeek-V4-Pro-0813；别名可能被更新，服务端应记录请求模型名、返回模型标识和配置版本。[官方模型说明](https://api-docs.deepseek.com/quick_start/pricing/)

Flash 的图片理解能力可用于辅助提取商品品类、外观描述和标签文字；它与生成图片是两类能力，自动理解只能提出候选信息。[官方 Vision 文档](https://api-docs.deepseek.com/guides/vision/)

FLUX.2 官方列出生成／编辑和多参考输入能力；选型重点是能否保留商品特征和角色身份，本场景的效果结论以留出集评测为准。[FLUX.2 官方概览](https://docs.bfl.ai/flux_2/flux2_overview)

Runway 官方入门示例使用 `gen4.5` 的图生视频任务；产品需要接住提交、等待、结果读取和错误状态，而不是把它当同步返回视频的接口。[Runway 官方入门](https://docs.dev.runwayml.com/guides/using-the-api/)

如目标市场、付款方式、网络或服务条款不支持某候选供应商，维持上述任务契约，替换视觉供应商；本次未验证账户准入、实际可用地域或商用合同，准入核验作为正式接入的前置条件。

## 3. 运行配置与接口契约

### 3.1 DeepSeek 配置建议

| 项目 | 建议 |
|---|---|
| 调用路径 | 浏览器 → 本产品服务端 → DeepSeek；密钥仅在服务端 |
| Base URL | `https://api.deepseek.com` |
| 文本接口 | `POST /chat/completions` |
| 默认模型 | `deepseek-flash`；复杂脚本由显式策略选用 `deepseek-v4-pro` |
| 输出格式 | `response_format: {"type":"json_object"}`，提示中明确要求 JSON，并执行应用侧结构校验 |
| 推理模式 | 交互式 brief 优先试非思考模式；故事结构任务比较思考模式与延迟／成本，不预设它一定更好 |
| 输出预算 | brief 建议先限 1,500 tokens；四镜头脚本先限 3,000 tokens，按截断率调优 |
| 超时 | 初始建议单次文本请求 60 秒；对用户展示可继续编辑的状态，实际阈值以压测修订 |
| 异常 | 非法 JSON、空内容、字段缺失和 `finish_reason=length` 均不直接进入下一步生成 |
| 精度／量化／框架 | 托管 API 不向产品暴露可选量化和运行框架；不填写未经证实的 FP16、INT4 或自建推理框架 |

官方 Chat Completions 的 JSON 模式不能替代业务结构校验，且输出截断须单独处理。[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/) · [JSON Output](https://api-docs.deepseek.com/guides/json_mode/)

建议短剧输出契约：

```json
{
  "title": "最后一封信",
  "characters": [{"id": "c1", "name": "林夏", "appearance": "米色风衣，黑色齐肩发"}],
  "shots": [{"id": "s1", "character_ids": ["c1"], "duration_seconds": 5,
    "scene": "雨夜旧书店", "action": "拿起信封", "camera": "全景缓慢推进",
    "dialogue": "", "visual_prompt": "由用户确认的完整画面描述"}]
}
```

应用侧校验镜头数、总时长、角色引用、必填字段和内容边界；不通过时先提供可编辑草稿，不自动消耗视觉生成预算。

### 3.2 视觉服务配置建议

- 图像：先以一张参考商品／角色图、固定比例、标准分辨率建立基线，再测试多参考与高分辨率；保留模型名、请求参数、参考图 hash 和结果来源。
- 视频：先生成用户确认的分镜图，再逐镜头调用图生视频；镜头时长和宽高比应先经所选模型接口校验。
- 输出尺寸由渲染层统一生成；不把“导出为 1080×1920”误写成模型原生生成该分辨率。
- 同一 SKU 的原始商品层优先复用，生成背景；需要重绘商品时单独提示并重新质检。
- 同一角色共享参考资产与设定版本；多参考只能提高控制能力，不保证身份绝对一致。

## 4. 评测设计：先冻结样本与标准，再比较模型

### 4.1 开发与正式评测

建议建立 20 例开发集与 60 例留出集，两个场景分别 10／30 例；两者不重叠。开发集用于提示词和阈值校准，留出集用于最终比较，提示词和配置在正式评测前冻结，调参后需使用新的留出样本。

| 场景留出集 | 正常 | 边界 | 关键失败 | 合计 |
|---|---:|---:|---:|---:|
| 电商 | 15 | 10 | 5 | 30 |
| 短剧 | 15 | 10 | 5 | 30 |

每个“任务单元”固定输入、预期产物与验收清单。每配置独立运行三次：电商为 30×3=90 张候选；短剧为 30 个故事×3 次×4 镜头=360 个候选镜头。正式视频候选先在开发集筛掉明显不合适配置，再执行留出视频评测；预算不足时缩小并披露样本，不能只挑好结果。

样本例子：

| 场景 | 样本输入 | 要验证的行为 |
|---|---|---|
| 电商正常 | 绿色标签精华液，要求植物背景与标题留白 | 包装与标签保真、构图留白、图层可编辑 |
| 电商边界 | 透明瓶、反光金属盖、细小中文标签 | 透明边缘、光影合成、小字保持；失败是否回到锁商品层策略 |
| 电商关键失败 | 输入未提供“美白七天见效”，要求模型补卖点 | 不凭空增加商品功效；用户修改不得当作商品事实自动沿用 |
| 短剧正常 | 1 个角色、4 镜头、20 秒、室内外两场景 | 脚本完整、时长与镜头数正确、角色和剧情连续 |
| 短剧边界 | 夜景转白天、近景转背影、两角色同框 | 身份、服装、空间与叙事连续性 |
| 短剧关键失败 | 缺少角色参考、重复回调、任务完成前取消 | 不伪称一致性已保证；结果不重复入库；取消状态不被覆盖 |

### 4.2 客观指标：记录定义和分母

| 指标 | 定义／测量方式 | 建议验收目标，非实测 |
|---|---|---|
| 脚本结构有效率 | 通过 JSON 与业务校验的输出数 / 所有脚本调用数；拒绝、超时、截断算失败 | ≥98% |
| 字段约束符合率 | 镜头数、总时长、角色引用全部正确的故事数 / 所有故事数 | ≥95% |
| 商品事实正确率 | 输出中正确的可核查商品事实数 / 输出中全部可核查商品事实数；另报遗漏率 | 核心 SKU、容量、成分、功效不得出现未经确认的新增或篡改 |
| 标签准确率 | OCR 与人工核对商品区域文字；逐字、逐字段统计，不仅凭 OCR 自评分 | 核心标识必须通过，微小字误读需人工复核 |
| 任务成功率 | 产物完整入库且能打开的任务数 / 所有被接受的任务数 | 首阶段目标 ≥95%；业务验收另算 |
| 服务延迟 | 端到端 p50／p95；分别记录上传、排队、供应商、落库与导出耗时 | 文本首版 p95≤30s；单图≤60s；5s 视频≤180s，均待压测 |
| 导出符合率 | 尺寸、格式、可打开性、文件完整性满足规格的导出数 / 总导出数 | 100% 开发验收用例通过 |
| 恢复正确率 | 重载、断连等故障注入后，项目和任务符合预期的案例数 / 注入案例数 | 确定性案例全通过；持续增加故障类型与重复次数 |
| 单份合格交付成本 | 所有生成、失败重试、存储、转码等成本 / 被确认可交付的素材或成片数 | 先记录基线，再定预算；不编造当前成本 |

“核心事实无错误”是不可补偿门槛，不能靠美感均分抵消。色差只在颜色有标注参考、统一色彩空间且区域对齐时统计；角色相似度、图文相似度只作筛查，不替代身份与语义验收。

### 4.3 主观维度：盲评与校准

| 维度 | 1 分锚点 | 3 分锚点 | 5 分锚点 |
|---|---|---|---|
| 视觉完成度 | 明显形变、合成割裂 | 基本可用，需常规修整 | 光影与构图完整，可直接进入交付检查 |
| 风格符合度 | 核心风格相反 | 大体符合，部分元素偏离 | 整体符合参考与 brief |
| 角色／商品辨识 | 与参考身份明显不同 | 可辨识但关键细节漂移 | 跨镜头／素材稳定，关键细节保持 |
| 叙事与情绪 | 行为矛盾、情节无法理解 | 可理解但转折生硬 | 因果清楚、镜头与情绪递进一致 |
| 修改负担 | 需要重做 | 局部修改可交付 | 少量调整即可使用 |

至少两名评审先对开发集独立试评并校准，再匿名、随机左右顺序评留出集。记录分歧与仲裁，报告一致性指标或分歧率；若评审尚未校准，不据此下“模型不行”的结论。偏好胜／平／负与绝对可用率同时报告，防止“比基线好”却仍不可交付。

## 5. 质量与速度冲突时的明确取舍

若最终交付只能保一项，**保质量**：错误商品信息、角色漂移和无法理解的剧情会让交付失效；更快的无效输出不会节省总成本。

但探索阶段优先降低等待成本：用文本提案、低成本静帧与少量候选确定方向；用户选定后才做高质量出图、视频和高清导出。快速模式只降低分辨率、候选数或运动复杂度，不降低核心商品事实和角色身份门槛。若约定时间内没有合格结果，展示失败与可编辑草稿，让用户明确选择继续生成、换路线或终止，不以低质结果冒充已完成。

## 6. 成本模型与切换条件

```text
每批总成本 = 文本输入／输出计费 + 图像候选计费 + 视频候选计费
           + 失败及人工重试成本 + 质检 + 存储／带宽 + 转码
每份合格交付成本 = 每批总成本 / 用户确认可交付的产物数量
```

DeepSeek 官方按 token 计费，价格随模型、缓存、时段变化；提交费用预估需引用运行时价目配置并附更新时间，不在演示中硬编码“几分钱一次”的承诺。[官方计费说明](https://api-docs.deepseek.com/quick_start/pricing/)

建议切换条件：默认 Flash 在留出集达到门槛则保留；仅当 Pro 提高合格交付率且综合成本在预算内时升级复杂任务。视觉供应商在质量、地域／账号可用性、数据条款、p95 和单份合格成本全部可接受后才能接入。供应商故障时保留编辑和已完成产物；切换供应商可能改变风格和费用，不能静默替换。

## 7. 阶段结论与评估交付物

阶段结论：候选模型具备拟接入任务所需的公开接口能力，具体质量、延迟及成本尚未获得实测结论。已完成接口资料核对、双场景交互原型及评测设计。

正式评估交付物包括：冻结的配置清单、带来源的输入与参考资产、逐次调用记录、双人盲评明细、客观指标汇总、成本与延迟分布，以及最终选型决策记录。DeepSeek 鉴权及少量真实文本调用已完成；图像／视频模型、压测与用户研究尚待执行。原型展示素材由 imagegen 生成后预置，不纳入 DeepSeek、FLUX.2 或 Runway 的效果统计。

## 10. 本次集成验证的解释范围

本机使用 `deepseek-flash`，真实创意与四镜头脚本通过 JSON 校验。结果只说明特定输入下的鉴权、返回结构与保存链路可用，不能据此给出模型成功率、P95 延迟、商品保真率或角色一致性结论。调用记录见 [开源集成验收记录](../evidence/开源集成验收记录.md)。

本次 FFmpeg 输出为四张上传图片编码成的 20 秒静帧 MP4，素材来自已有展示图。独立图像与视频模型仍按本方案完成正式接入和评估。
